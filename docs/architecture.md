# 강의 생성 흐름과 State

## 역할을 나눈 생성 단계

`node_parse_all`은 PPT를 한 번 열어 제목·텍스트·표·이미지·도형 텍스트를 수집합니다. 전체 슬라이드 스냅샷은 레이아웃을 포함한 시각적 근거입니다. PDF는 실행 폴더에 보관하여 각 슬라이드마다 다시 변환하지 않습니다.

검색 노드는 슬라이드 제목과 본문 일부를 질의로 사용합니다. 제외 도메인을 결과에도 적용하고 URL을 중복 제거합니다. 같은 순서의 출처·스니펫을 내용 생성에 전달합니다. 검색은 슬라이드 설명을 보완하며, 벡터 인덱스나 임베딩은 사용하지 않습니다.

내용 생성과 대본 생성을 분리합니다. 앞 단계는 근거를 정리하고, 뒤 단계는 `전체 목차 + 현재 요약 + 직전 대본 + 장별 지침`으로 설명 흐름을 구성합니다. 전체 이전 대본을 매번 모델에 넣는 구조와 구분됩니다.

## 주요 상태 계약

| 필드 | 자료형 / 의미 | 생산 → 소비 |
|---|---|---|
| `titles`, `texts`, `shape_texts` | 슬라이드 순서의 문자열 리스트 | PPT 분석 → 내용/대본 |
| `tables` | 슬라이드 → 표 → 행 → 셀 | PPT 분석 → 내용 |
| `images` | 슬라이드 → 그림 경로 리스트 | PPT 분석 → 내용 |
| `slide_image` | 전체 슬라이드 PNG 경로 리스트 | 렌더링 → 내용/영상 |
| `slide_index`, `total_slides` | 현재 0-based 번호 / 전체 장수 | 분석·누적 → 반복 분기 |
| `page_content`, `script` | 현재 슬라이드의 설명 / 대본 | 내용 → 대본 → TTS |
| `all_scripts` | 슬라이드 순서의 대본 리스트 | 대본 → 다음 대본/퀴즈 |
| `slide_videos` | 슬라이드 ID → 영상 경로 | 영상 → 순서 검증 |
| `video_paths` | 검증을 마친 순서대로 정렬한 영상 | 누적 → 병합 |
| `quiz_set` | 질문·선택지·정답 6문항 | 퀴즈 → UI/JSON 저장 |

## 대본의 흐름

- 한 장짜리 입력은 도입·본문·마무리를 함께 구성합니다.
- 여러 장의 첫 장은 직접 인사 없이 강의를 소개합니다.
- 중간 장은 직전 대본에서 본론을 이어가고 다음 주제로 짧게 연결합니다.
- 마지막 장은 전체를 정리하고 끝인사를 포함합니다.

`prompts.py`에서 이 규칙을 검토할 수 있습니다. 개인 GitHub 고도화 버전의 다음 주제 연결 방식을 기준으로 현재 프롬프트를 구성했습니다. 과거 노트북의 특정 버전과 프롬프트가 같다고 가정하지 않습니다.

## 한 번의 실행을 완성하는 방식

1. 업로드 경로·형식·슬라이드 수·목표 분량·음성 속도를 확인합니다.
2. 실행마다 고유한 폴더를 만들고 PPT를 복사합니다.
3. 슬라이드 ID로 대본과 영상을 저장합니다. 현재 장의 영상이 없으면 불완전한 강의를 병합하지 않습니다.
4. 장수에 맞춰 그래프의 실행 한도를 계산합니다.
5. 전체 영상 이후 퀴즈를 생성합니다. JSON 형태·문항 수·선택지·정답 일치를 검사하고 형식 오류는 한 번 재요청합니다.
6. 영상과 대본, 퀴즈, 실행 옵션을 함께 보관합니다. 퀴즈 생성이 완료되지 않아도 이미 만든 영상은 전달합니다.

API 클라이언트는 생성 단계에서 초기화하므로 키 없이 UI를 열고 코드 검증을 실행할 수 있습니다. 서버는 기본적으로 로컬에서 실행합니다.
